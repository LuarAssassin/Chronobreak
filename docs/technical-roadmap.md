## 1. 概要、愿景与边界

Chronobreak 的目标是一个 **Rust 原生、保留 UI 树、自绘的桌面 GUI 框架**：应用开发者用可组合的 Rust API 表达界面、绑定状态、处理交互；框架负责节点生命周期、更新调度、布局与文字、绘制及平台适配。成果必须能够支撑一个真实应用的持续修改，而不只是展示计数器。

已确认的实现方向不再重复投票：**原生 builder 先于宏 DSL，显式 Signal，taffy + cosmic-text/glyphon + wgpu + winit**。保留模式是长期存在的节点与交互身份；Signal 是依赖通知机制，两者组合不要求 React 式重新运行组件、虚拟树 diff 或 hook。现有组件函数是 Rust 构造函数，未来动态结构由明确的挂载、卸载和 keyed 集合操作表达，不靠普通 `if` 自动重新执行。

### 1.1 产品边界

- **框架内**：UI 构造与组合、状态绑定、场景树、布局与文字、输入与编辑、视觉原语、少量可靠控件、平台服务、语义无障碍、调试与验证设施。
- **验证应用内**：知识文档 schema、prompt、LLM 客户端、组织分类与本地文件。已选“有真实用途的组件/知识整理工作台”，以粘贴→显式整理→树形思维导图→本地恢复验证框架，不是同时建设两款独立应用；业务逻辑不渗入 `Application`。详见 [核心规格](knowledge-workbench.md)。
- **不是完整应用**：框架示例不等于任务管理器、设备平台或 IDE 的产品交付；真实验证应用也不是承诺建设整套业务生态。
- **不是 3D/游戏引擎**：不自建 ECS、物理、材质、游戏资源管线、持续游戏循环。动画需要按需时钟，不把 GUI 改成常驻 60 FPS。
- **首轮不承诺**：Qt 级控件覆盖、浏览器级 CSS、富文本/代码编辑器、插件市场、跨语言 ABI、所有桌面平台同时可用、Web 和移动端。多窗口、复杂弹出层、拖放等按验证应用需求单独立项。

### 1.2 设计原则

1. **从真实使用收敛 API**：先打通一个有输入、列表、异步结果和错误状态的使用闭环，再扩展控件目录。
2. **身份与生命周期先于语法糖**：节点删除、订阅取消、焦点转移和资源回收必须可解释；语法简洁不能掩盖所有权。
3. **增量更新不等于局部 GPU 呈现**：尽量减少状态、测量和布局工作，但首轮允许脏帧全帧绘制，不提前追求损伤区域渲染。
4. **成熟库负责标准，框架负责契约**：不重写 Flexbox、整形或窗口系统；库能调用不代表编辑、IME 和平台行为已集成正确。
5. **证据先于扩张**：每项能力具有运行例子、回归与限制记录；依赖替换、性能优化、平台承诺都需要实测或可复现缺陷。
6. **有限切片交付**：底层逻辑可并行，公共 API 与所有权改动先审查；不以自动长跑或无上限功能列表替代验收。

## 3. 源码基线与原文五层对照

原方案编写阶段已实际阅读原文、本地 `source.json` 的来源结构、`Cargo.toml`、公共导出、全部核心实现、两个示例、架构和历史验收文档；以下保留原方案源码分析，不声称本次重新核验全部源码。分析基线为单 crate、`publish = false`；直接依赖 glyphon 0.9、taffy 0.7、wgpu 25、winit 0.30 等，cosmic-text 经 glyphon 使用，具体组合以 `Cargo.lock` 为准。

### 3.1 当前公共 API 与关键文件

- `src/lib.rs`：导出 `Application`、`Element`、`Signal`、`Result`；`signal`、`ui` 为公开模块，`Scene`、`Node`、`Paint` 均为 `pub(crate)` 内部类型。公开模块中的 `Bounds`、`Color`、`Subscription` 等同样需要纳入 API 变更审查，不能只检查顶层 re-export。
- `src/application.rs`：`Application::new(root).title(...).run()`；管理单窗口、事件循环、DPI、遮挡/暂停、指针位置与呈现重试。
- `src/ui.rs`：`Element::column/text/bound_text`，`child/padding/gap/max_width/background/font_size/on_click/visible`；负责一次挂载、绑定同步、文字测量、布局、裁剪、显示列表和点击命中。尚非完整样式 API 或标准控件库。
- `src/signal.rs`：`Signal::new/get/update/subscribe/subscriber_count`，`Rc<RefCell<_>>`，值不变不通知；`Subscription` drop 取消监听。
- `src/render.rs`、`src/rect.wgsl`：矩形三角形绘制、glyphon 文字、继承裁剪和顺序提交；矩形着色器还不是 SDF。
- `examples/counter.rs`、`examples/state_panel.rs`：业务状态与组合函数；没有手写 Scene、Renderer 或请求重绘，说明复用内核已从 demo 中分离。
- `docs/architecture.md`、`docs/reusable-core.md`、`docs/minimal-gui.md`：当前边界与历史证据；`CONTRIBUTING.md` 和 `.github/workflows/rust.yml`：协作约定及 `Rust checks` 内容。

### 3.2 原文五层的落地差距

| 原文层次 | 基线已实现 | 主要未做与不得混淆之处 |
| --- | --- | --- |
| 1. DSL 与组件 | Rust builder、普通 Rust 组合函数、泛型文字绑定 | 无宏 DSL、组件作用域协议、完整控件体系；不需要先造宏才能继续 |
| 2. 保留树与增量更新 | 一次 mount，`Vec<Node>` 与 taffy 节点保留；按节点/属性合并待更新值；节点持有 RAII 订阅 | 无通用删除/插入/移动、keyed 列表、派生图和事务；`visible` 使用 `Display::None` 保留整棵子树及订阅，**不是动态树** |
| 3. 测量与定位 | taffy Flexbox，cosmic-text 真实测量/中文换行，最终宽度再整形，布局缓存失效 | 无滚动容器/虚拟列表、完整约束与溢出策略；不能据底层支持推定公开 Grid 已交付 |
| 4. 显示列表与 GPU | 父背景→父文字→子节点的顺序；矩形 scissor、文字 bounds；glyphon 图集；脏帧全帧绘制 | `Paint::Text(usize)` 回查 Scene 的 buffer、颜色与 bounds，Renderer 直接借用 `&mut Scene`，**不是完全自包含或可序列化 IR**；无圆角边框阴影、图片与顺序安全合批 |
| 5. 窗口与事件 | winit 单窗口、物理/逻辑坐标、左右边界一致裁剪、左键同目标按下/松开触发、空闲 Wait、surface 延时重试 | 无通用 capture/bubble 路由、hover/焦点/键盘/IME、滚轮、后台唤醒、剪贴板、AccessKit 和平台发布闭环 |

当前核心是**固定拓扑、单窗口、显式属性绑定的信息面板**，不是动态组件系统。当前命中从绘制逆序递归寻找带 `click` 的节点，不是先返回任意最深节点再沿父链冒泡。指针离开、失焦、尺寸变化会取消按压；这不是指针捕获。现有 `Scene::sync` 对所有变更标记布局脏，`Application` 每次重绘仍调用布局/显示列表生成；节点更新合并不等于整条流水线均已细粒度增量。`pointer_button` 会先 `sync`，但不重新 layout：外部更新或动态树接入后，必须明确状态提交、命中与呈现几何快照的先后顺序（见 M1/M2）。Renderer 当前遍历所有有 buffer 的节点准备文字，包含隐藏节点；`TextRenderer` 数组只随节点数增长并按下标对应，隐藏不绘制不等于没有准备成本，动态卸载也不能沿用此索引假设。

### 3.3 已有证据的精确边界

**历史验证**：先前交付报告 19 项单元测试和 1 项文档编译测试通过，并已完成相关 PR/Rust checks。仓库内 `reusable-core.md` 主要保存本地命令与图形记录；远端结果应以对应 PR/CI 为准，本轮不补造运行链接或重跑声明。

图形记录为 Linux、Xvfb/X11、llvmpipe 软件 Vulkan、Mesa、Noto CJK；真实 wgpu surface 与 XTEST 输入验证了中文绘制、独立计数、绑定、显示恢复、缩窄换行、裁剪、启动时 1.5 DPI 及空闲无连续重绘。**软件 Vulkan 不等于硬件 GPU 实测**，启动时指定 DPI 不等于多屏动态 DPI。原生 Wayland、其他桌面、IME、无障碍、真实 device lost 等仍无完成证据。历史逻辑注入覆盖 surface 错误分类与 100ms 重试，不冒称系统/GPU 故障实测。

## 4. 目标架构、数据流与所有权

以下是 **计划架构**，不是立即拆模块、拆 crate 或承诺每层一个 trait。

```text
应用模型 + Rust builder / 组件组合
              │ mount / keyed 结构操作 / 显式绑定
              ▼
稳定 NodeId 的保留场景树 ─────────────→ 可访问语义树 → AccessKit
              ▲                            ▲
Signal / 派生关系 → 更新队列 → UI 调度器 / 脏原因
              │                            │
              └──── 树与属性提交 ───────────┘
                          ▼
              taffy 布局 ↔ 文字测量/整形
                          ▼
            顺序显示列表 + 有版本的资源引用
                          ▼
                 wgpu / glyphon → surface
                          ▲
winit / 平台服务 → 输入路由 → 回调 → Signal
工作线程 → 有界消息 + EventLoopProxy → UI 调度器
```

### 4.1 每次 UI 提交的阶段

1. 接收系统输入或用户事件；把物理坐标转换为逻辑坐标。先冻结几何提交契约：命中与呈现使用带版本的布局快照，不能属性已更新而 bounds 仍旧。存在未提交变化时，是先完成树/布局并安排对应呈现，还是将输入绑定到上一已呈现快照，须在 M1 确定；M2 所有入口沿用同一顺序，不能各自临时 `sync`。
2. 对有效 NodeId 路由事件；事件分发期间禁止即时破坏正在遍历的树，结构变更进入 UI 提交队列。回调仅修改状态或提交动作，不在其中布局、画 GPU 或阻塞 I/O。
3. 合并同一提交批中的属性变更和 keyed 结构操作，验证节点代际与作用域；卸载清理优先于向已失效目标应用更新。
4. 根据脏原因安排文字/布局/绘制/语义更新。文字内容、字号、约束影响测量；颜色通常只影响绘制；焦点、语义值另有对应脏域。初期可保守扩大脏范围，再依据计数器优化。
5. 布局约束驱动文字测量，最终宽度对应最终字形位置；构建保持遮挡顺序的显示列表，准备资源并提交 GPU。
6. 呈现失败保留待呈现意图，不依赖第二次输入才能重试；没有动画、重试或消息时回到休眠。

### 4.2 线程与资源所有权

| 所有者 | 持有内容与边界 |
| --- | --- |
| UI 线程 / Application | winit 事件循环、窗口状态、Scene、调度器、焦点/捕获/IME、UI Signal；首轮所有场景变更在此串行 |
| Scene / 组件作用域 | 稳定节点槽位、父子关系、布局映射、绑定订阅、局部状态与资源引用；作用域退出统一释放 |
| 文字服务 | FontSystem、排版 buffer、测量缓存；先留 UI 线程，后台整形必须有性能证据与快照协议后再议 |
| Renderer | surface、device/queue、管线、图集、GPU buffers；不拥有业务状态，目标不再依赖节点数组位置 |
| 工作线程 | I/O、设备采样、解析等及其线程安全数据；只能通过消息提交结果，不携带 `Rc` Signal 或可变 Scene |

计划 NodeId 使用槽位+代际或等价的失效检测，不复用裸下标身份；taffy ID 为 Scene 私有映射。节点、文字布局、图片和 GPU 缓存各有独立寿命；卸载移除 CPU 引用后，GPU 资源须遵守 wgpu 的在途提交寿命，不手动复用仍被命令引用的资源。

### 4.3 从现有显示列表走向资源引用

分两步解耦，避免先造一个通用矢量文档格式：

- 第一步：动态树引入稳定身份后，去掉 Renderer 按 `nodes.len()` 扩容并用相同下标缓存文字的假设；建立可失效、可删除的文字资源映射。
- 第二步：显示列表引用 `TextLayoutId + revision`、`ImageId` 等逻辑资源，命令携带绘制位置、裁剪和颜色，Renderer 通过只读帧资源视图取数据。用真实生命周期需求确定句柄形状，不把 NodeId、taffy ID、GPU 对象混为一个 ID。

资源表与帧快照可以仍在进程内借用；这不自动支持存盘、网络传输、PDF 导出、CPU 渲染或渲染线程。仅当重放测试或第二后端确有价值时再设计序列化与后端 trait。帧资源缺失/过期必须有确定处理和诊断，不可错画成新节点内容。

### 4.4 错误与 surface 生命周期

已实现：Lost/Outdated 重配后返回 Retry，Timeout/Other 返回 Retry；Application 至少间隔 100ms 重试，成功恢复 Wait；OutOfMemory 等错误上报并退出；零尺寸/遮挡不画，暂停丢弃 Renderer/Window，恢复重建。

计划补齐状态表：未创建→可绘制→零尺寸/遮挡→恢复；暂停→重建；可恢复 surface 失败→延时重试；不可恢复 device/内存/初始化失败→明确报告与安全退出。暂停保持 CPU 业务状态但清掉指针捕获、焦点相关临时输入和未完成组合；重建后重新上传资源。device lost 与 surface lost 分开验收；首轮允许 device lost 受控退出，不承诺完整设备热恢复。

输入错误、资源解码错误应变成可观察的应用结果/占位状态；内部不变量失败与应用回调 panic 不伪装成普通重试。当前仍有内部 `unwrap` 与通用 boxed error，后续按真实可恢复路径改进，不以全面 `catch_unwind` 或无穷重试隐藏损坏状态。

## 5. 核心能力技术路线

### 5.1 动态树、keyed 列表与调度（M1a→M1b→M1c）

先定义 mount/unmount/move/replace 及作用域退出顺序，再增加便捷构造 API。key 在同级列表内唯一，重复 key 返回明确诊断；重排保持节点、局部状态、订阅和焦点身份；删除后重新使用相同业务 key，不复活已卸载的旧 NodeId。业务模型若需跨卸载保存，由应用持有。

卸载必须同时处理：父子链接、taffy 节点、订阅、待更新值、延迟回调、按压/捕获/hover/焦点、IME、文字资源及异步结果目标。已复制的 Signal 回调可能仍运行，故 **drop 订阅不等于撤回在途消息**；入队与消费时校验代际/作用域，过期项丢弃。隐藏继续保留状态与订阅，与卸载并存；不能用隐藏无限堆积已删除列表项。

当前 Signal 同步通知，更新闭包持有借用；订阅回调在释放借用后执行，监听器列表先复制。**M1 优先风险（源码控制流推导，本轮未运行复现）**：初值 0，先注册监听器 A（收到 1 时递归写入 2），再挂载绑定 B；外层写 1 后，A 触发内层通知，B 先入队 2，外层继续又让 B 入队 1，最终 pending 为 1 而 `Signal.get()==2`。这可不触发借用 panic，却使界面回退到旧值。M1b 先确定入队、单调版本与通知顺序，再实现两个层次：

- **UI 批处理**：事件结束统一 flush，节点同属性只应用最终值，重绘请求合并；所有框架入口产生的可见更新必须能唤醒调度器，不能只依赖 `on_click` 返回值。
- **Signal 通知契约**：明确 `get`、监听器参数和批边界各代表哪个版本；选择串行通知队列或等价的版本淘汰规则，保证旧通知不能覆盖新绑定值，并确定取消订阅与在途通知的关系。递归写入有确定顺序与循环诊断；禁止在 `update` 闭包中读写同一 Signal。先用上述精确序列建立回归，再迁移公开通知行为，不只防 `RefCell` panic。

显式派生/菱形图为 **M1b 后的条件扩展**，由真实需求触发，不阻塞生命周期首切片或最小唤醒。纳入时先限定依赖集合与纯计算、拓扑去重，验收菱形批末一致、循环拒绝或诊断。通用 effect、自动依赖追踪与复杂事务回滚不进 M1；优先完成稳定身份与卸载、Signal 调度契约、后台唤醒。

### 5.2 布局、滚动与虚拟列表（M2，虚拟化为条件项）

维护「约束→文字测量→taffy→最终排版」闭环，测量缓存键包含文本版本、字体/字号/行高、换行策略和约束；字体回退或字体集合变化使相关缓存失效。验证 min/max/definite width、空文本、长词、中英混排及隐藏恢复，不把简单行数乘行高扩展为所有富文本的通用方案。

滚动拆成 viewport、内容尺寸和逻辑 offset：布局测内容，绘制/命中统一施加 offset 与祖先 clip，偏移在内容或窗口变化后 clamp。滚轮像素/行单位与平台方向要归一；嵌套容器先消费可滚动部分，剩余量是否上交形成明确契约。增加 `scroll_into_view` 支撑焦点和光标，而不是每个控件各写偏移逻辑。首版只做轴对齐矩形裁剪，圆角裁剪单独估价。

虚拟列表不与滚动绑定为同一必做项：先在已选应用上测节点数、排版与内存，超预算再进入。优先固定高度行、可见区+overscan、keyed 身份；卸载不可见行时，数据与选择状态放在应用模型。可变高度估计、滚动锚点修正、超大文件按块加载是后续切片，不承诺首轮全部完成。

### 5.3 统一事件、焦点与快捷键（M2）

构建目标路径，按 **capture→target→bubble** 派发；区分停止传播、阻止默认行为和业务已消费。只停止传播不应意外阻止默认聚焦；快捷键作用域和文本输入优先级要可预测。第一版以单指针/鼠标为主，不把触控手势一并承诺。

框架拥有 hover 路径、pressed、pointer capture、focused NodeId 与 focus scope。捕获用于拖动/文本选择：越出控件仍可收到移动/释放；窗口失焦、系统取消、节点卸载时可靠释放。普通按钮仍需要可取消点击语义，不能获得捕获后在任意位置释放都触发。

Tab/Shift+Tab 顺序稳定，隐藏/禁用节点跳过；节点移除时焦点回退到可解释位置。鼠标、Enter/Space 和语义默认动作复用同一控件激活逻辑。快捷键区分物理键、逻辑键、修饰键与平台约定；IME 组合期间不得把所有按键抢作全局快捷键。视觉焦点、hover 与指针图标是交互状态的投影，不是单独业务 Signal 拼凑。

### 5.4 文本编辑与 IME（M3）

先做可靠单行输入与真实 IME，保留为框架 Alpha 目标。已选工作台首版可用“粘贴按钮读取剪贴板 + 只读源文预览”，不以完整多行编辑器阻塞业务闭环；若用户需要在应用内编辑原文，再确认多行切片。只增加键盘字符串并不是文本编辑。

1. **编辑模型**：UTF-8 文本、selection anchor/focus、光标亲和位置和编辑动作。字节索引用于存储，grapheme/词边界用于移动与删除，整形结果用于点选和视觉位置；combining mark、emoji ZWJ、连字与双向文字不能按字节切开。
2. **单行交互**：插入/删除、左右/Home/End、Shift 扩选、拖选、全选、复制/剪切/粘贴、只读/禁用、水平滚动与受控光标闪烁。撤销/重做先确定编辑事务边界，不能与 Signal 的值回写形成重复操作循环。
3. **IME**：preedit 不直接污染已提交模型；记录组合范围及选择/下划线，commit 只插入一次，取消恢复原值。焦点改变、组合中删控件、窗口失焦、粘贴等须定义结束/取消策略；不同平台行为以系统测试确认，不猜测统一事件序列。
4. **候选定位**：光标的文本局部矩形经过滚动、祖先偏移、窗口坐标与 DPI 转换，按对应 winit 接口要求提交 IME 区域；窗口移动、滚动、重排、DPI 变化时更新，不能只在输入时更新。用真实输入法确认候选窗跟随而非截图中画一个假候选框。
5. **多行条件切片**：换行、上下移动的视觉 x、段落/行选择、垂直滚动、编辑事务与文件换行规范。代码高亮、富文本、多光标、大文件编辑和语言服务均不默认纳入。

cosmic-text 的 buffer/编辑支持作为基础，框架仍负责事件、选择、焦点、剪贴板和 IME 生命周期；不能以库提供 editor 类型宣称这些已完成。

### 5.5 后台任务与外部唤醒（M1c 最小闭环，M5 扩展）

工作线程只发送 `Send` 的结果/消息，UI 线程读取后更新自己的 `Rc` Signal。用 **有界消息通道 + `EventLoopProxy` 用户事件** 唤醒休眠的 winit 循环；proxy 是通知，不把所有大载荷塞进事件队列，不强行给现有 Signal 加 `Send/Sync`。

消息附任务/目标代际或请求编号，旧查询结果不能覆盖新查询，卸载后结果无效。UI 每次按条数或时间片排空，剩余工作继续调度，避免消息洪峰饿死输入。队列容量与批量大小由测量确定；遥测允许合并最新值，编辑/保存结果不可静默丢失，应返回背压或错误。仅合并唤醒时，要测试生产者与消费者竞态，确保不会“队列非空但事件已丢”。

关闭/取消至少包括停止接收新工作、通知任务取消、丢弃过期结果及退出期限；不可在 UI 回调里无限等待线程 join。先用标准线程/通道或一个最小实现满足需求；是否引入异步运行时由真实网络/设备库要求决定，不作为框架默认前提。

### 5.6 绘制原语、资源与颜色（M4）

先在现有 wgpu/glyphon 上增量推进：

- 矩形→圆角矩形/边框→有限阴影，优先 SDF 与抗锯齿；明确边框内外、阴影扩展 bounds、clip 行为。复杂路径、模糊链和离屏特效不是 SDF 几行代码即可覆盖。
- 保留画家顺序，先合并连续且管线/纹理/clip 兼容的命令；跨文字与矩形的全局类型排序禁止。扩大合批必须有不重叠或等价性证明。M1a 先取消按节点数组下标持有 TextRenderer 的身份假设；M4 再测每文字资源一个 renderer 的成本并决定合批。分别统计可见/隐藏/裁剪外文字的 prepare 次数与耗时、整形次数、上传量及缓存峰值；按显示列表的可达资源准备或采用有界缓存策略，避免只减少 draw 而不可见准备成本仍随总文本增长。
- 字形图集继续交给 glyphon；补资源峰值/驱逐/重建证据，不另造字形 atlas。图片先限定解码格式、尺寸上限、失败占位、缩放采样与释放；图片图集只有碎图和绑定开销构成瓶颈时再做。
- SVG 为条件项：先选经过维护的解析/栅格化库，限定支持子集和缓存尺度，不自建完整 SVG 引擎；字体、外部资源与安全加载边界要说明。
- 规定颜色 API 的空间、纹理 sRGB 解码、着色计算与输出策略，明确 straight/premultiplied alpha 的转换点。当前 `[f32; 4]`、glyphon 颜色转换和 alpha blend 不等于已建立统一色彩规范。用半透明交叠、文字/图片边缘与浅/深背景验证光晕。
- 布局用逻辑像素；矩形、文字、clip 在统一尺度进入物理像素，分数 DPI 下采用一致边界取整。高级色彩管理/HDR 不作为首轮要求。

### 5.7 主题、控件与语义（M4→M6）

主题先定义颜色、字体、间距、圆角、密度和状态 tokens；D4 已选统一自绘明暗两套，初始数值与使用规则见 [主题方向](theme-direction.md)，不先铺额外皮肤。控件用同一行为模型组合：Button、Label、TextInput、Checkbox/Toggle、ScrollView、List 是候选最小集合；工作台先取粘贴/整理/取消按钮、只读预览、滚动树节点及展开折叠，TextInput 仍按 M3/M4 交付，不强塞进业务首切片。每个控件包含正常/hover/pressed/focused/disabled/error 的相关状态、键盘动作和语义，不仅是背景+点击闭包。

M1 的稳定 ID 为可访问语义提供身份，M2 的焦点/动作与 M4 控件同步设计 role、name、value、disabled、focusable 等，不等 M6 再发明语义。AccessKit 桥接和真实读屏验收放 M6；语义树不必逐个复制装饰节点，隐藏节点移除语义，虚拟行的可发现/动作策略需单独声明。最低要求是键盘可完成主流程、焦点可见、按钮可读出名称、输入值/变化能被正确查询。

### 5.8 平台服务、文档与 API 演进（贯穿各阶段）

平台探针从 M1 开始：按已选 Linux-first 调查设备与 X11/Wayland、字体、唤醒和 DPI，声明只覆盖实测单元；保留跨平台架构，Windows/macOS 尚未实测。M2 验收系统输入和 IME 事件/定位探针，M3 完整验收编辑与真实输入法，M6 汇总平台资格。剪贴板可随 M5 粘贴按钮先做最小读取服务，M3 仍完整验收编辑复制/剪切/粘贴；平台文件对话框、打开 URL、光标和系统主题按主流程需要薄封装，不先造“大一统平台 trait”。多窗口和菜单只有真实应用需要时引入清楚的窗口身份及焦点/资源隔离。

保留单 crate，内部模块可拆分以降低耦合。公共 API 每次变化附迁移示例；组件组合、Signal 生命周期、动态列表、后台消息、编辑与自定义主题各有短文档。alpha 前允许破坏性更改，但要记录，而非承诺永久兼容；beta 的兼容范围和弃用周期必须另定。MSRV、依赖更新频率、功能开关由 CI 与用户场景决定，不跟随本机编译器版本任意宣布支持。

## 6. 基础依赖与架构分岔

| 方向 | 默认继续 | 何时重新评估及需要的证据 |
| --- | --- | --- |
| cosmic-text / glyphon | 保持当前可运行组合，先集成编辑/IME和缓存 | 必需的文字脚本/选择定位出现可复现缺陷、无法在合理补丁内修复，或剖析证实文字路径长期超预算；提供最小样例、上游状态、修补与迁移成本对比后，才评估 parley 等 |
| taffy | 继续 Flexbox，包装已需样式而非暴露全部选项 | 遇到真实布局规范缺口先验证接入/测量是否错误；不因一个换行 bug 重写布局引擎 |
| wgpu 渲染 | 现有后端增量加原语、资源管理和连续合批 | 选定平台缺失关键能力、驱动问题无合理规避，或测量证明主要成本在后端；同一场景比较画质、CPU/GPU、内存与维护成本后再提替换 |
| winit | 单事件循环与平台事件服务 | 输入/IME问题先定位桌面协议、适配与版本；上游限制确实阻塞平台完成线才评估绕过或补丁 |

parley 不是 glyphon 的直接替换按钮：文字布局、编辑定位与 GPU 绘制的集成边界都可能变化。试验必须在隔离分支比较同样字体、脚本、DPI、编辑动作与资源释放，成功后由用户批准范围变化。原文介绍备选库不构成替换理由。

**暂不做**：多 crate 拆分、通用插件/C ABI、宏 DSL、React 式全树 diff、游戏/3D、Web/移动端、多渲染器抽象。引入 trait 的触发条件是已有第二实现、必要的测试缝或清楚的外部扩展需求；资源句柄由动态树和帧寿命驱动，而不是为了“架构完整”预置所有层。此规则不禁止内部重构，只禁止在无需求时扩大公共承诺。

## 7. 交付里程碑与验收合同

### 7.1 依赖与范围规则

下述 M0—M7 按已确认的框架技术预览 **Alpha** 组织。M0 方向回填完成、基线方案已交付；M1—M7 均为 **计划，未实施**。具体实现合同仍需逐切片冻结，不等同全部需求冻结。不承诺八周完成完整 GUI 体系，不把一个里程碑等同固定两周 sprint。

```text
M0 → M1a 身份/卸载 → M1b 通知/flush → M1c 最小消息唤醒
M1b → M2 → M3；M1a → M4 资源/视觉基础
M2 → M4 控件行为；M3 → M4 TextInput
M5a schema/持久化：合同可先设计，不依赖 GUI；实现仍需后续授权
M1a/M1b + M2 + M4 最小节点/连接线/主题公开 API → M5b 离线树图
M5a/M5b + M1c + 最小剪贴板服务 + 网关合同确认 → M5c 真实单次调用 → M5d 失败恢复
M3 编辑/IME 为 Alpha 必选，与 M5 最小粘贴流程解耦；M5 + M3 + M4 必选合同 → M6 → M7
平台探针：M1 即开始 Linux 可用环境调查/最小运行；冻结协议/输入法/设备矩阵
系统输入/IME：M2 探针与输入验收 → M3 完整编辑/IME → M6 资格汇总
语义模型：M1 身份 → M2 焦点 → M4 控件 → M6 AccessKit 验收
```

M4 可先做视觉原语，但不能以截图通过宣称输入控件完成。M5 可先设计 schema 或用明确标识的离线 fixture 暴露需求，但树图、真实调用和最终闭环分别等待所需能力合入；fixture 通过不等于 LLM 已接通。虚拟列表、SVG、多行、额外平台等条件项一旦纳入，必须在对应合同写明，不隐含于“完整”。

统一完成规则：**验收项全部通过 + 独立 review + 适用的 Rust checks/CI + 可运行示例 + 文档/限制/证据索引**。某目标仅逻辑测试通过而缺系统证据时标记部分完成，不以测试数量代替结果。

### M1 — 分切交付生命周期与调度基础

- **前置**：M0 共同基础与四项方向已回填，先冻结本切片实现合同；每切片单独 review、验收与合入，不打包成一个大 PR。
- **切片与依赖**：
  - **M1a 身份与卸载**：可失效 NodeId、作用域、结构提交队列、最小 mount/unmount/move 与 keyed 操作；同步迁移文字资源至可删除映射，去除节点下标身份假设。仅为既有交互预留失效清理口，不提前实现全部焦点/IME。交付动态树小例子与生命周期计数。
  - **M1b 通知与 flush**（依赖 M1a）：先冻结通知入队/版本/重入契约，再实现批处理、脏原因、提交边界与几何快照顺序；交付调度轨迹及 API 迁移说明。派生/菱形库为条件扩展，不是本切片前置。
  - **M1c 最小消息唤醒**（依赖 M1b）：有界通道 + EventLoopProxy，工作线程结果在 UI 更新 Signal、触发 flush/重绘、恢复 Wait；附最小过期目标和关闭处理。M5 再依据 D1 扩展取消、洪峰预算与业务错误。
- **非目标**：虚拟列表、宏/自动依赖追踪、完整派生库、多线程响应式或并发树修改。平台最小探针可从 M1a 并行启动，不把所有系统测试塞入 M1。
- **分切验收**：
  1. **M1a**：`[a,b,c]` 插入/删除/重排保留存续 key 身份、局部值和订阅；重复 key 有诊断。排队更新→卸载→复用槽位后旧 ID/消息无效；同 key 重建不复活旧状态，隐藏恢复仍保留状态。
  2. **M1a**：1,000 次挂卸后活节点、订阅、pending、文字资源/renderer 引用回归基线；槽位压缩/复用不串字。记录可见与隐藏文本 prepare 次数/耗时及缓存峰值，不能只报节点数；完整不可见工作优化在 M4 验收。
  3. **M1b**：按第 5.1 节精确顺序注册 A、再挂 B，写 1 触发递归写 2；最终 `get`、flush 后绑定和呈现均为 2，旧版本不回退。记录通知轨迹、取消在途通知的规则和循环诊断；同批节点同属性只提交最终值。
  4. **M1b**：已布局后改变文字换行/可见性或插入节点，**不等下一次 redraw 即发送输入**；按已冻结快照合同断言命中与对应呈现版本一致，无“新属性+旧 bounds”。M2 扩展至全部输入入口。
  5. **M1c**：窗口 Wait 时后台消息唤醒并显示最终值；无额外点击也能重试临时呈现故障；合并唤醒不丢消息、队列有界、卸载目标无效、关闭不无限等待，空闲返回 Wait。
- **证据与判定**：每切片独立提交确定性回归、资源计数、真实运行例子及限制；M1a 放行资源/视觉基础，M1b 放行 M2，M1c 放行后台闭环，不以未做条件派生库阻断这些依赖。

### M2 — 统一输入、焦点与滚动

- **前置**：M1a/M1b 身份和提交边界；按 D2 Linux-first 冻结必验协议/设备矩阵；探针不自动形成平台支持承诺。
- **交付物**：事件路径、capture/target/bubble、消费/默认行为、hover/捕获、焦点/Tab/快捷键、基础 ScrollView 和 `scroll_into_view`；交互测试面板。
- **非目标**：触控手势、通用拖放、多窗口焦点、可变高度虚拟列表、文本编辑。
- **验收**：
  1. 三层嵌套节点的事件顺序与停止传播/阻止默认行为分别可断言；遮挡、clip、滚动后命中与实际显示一致；回归“状态改变布局→紧接鼠标/滚轮/键盘输入（未等 redraw）”，沿用 M1b 快照顺序，焦点滚入与动态插入亦覆盖。
  2. 拖动越出控件仍接收结束；失焦/卸载时清捕获，普通按钮拖出释放不激活；hover 路径离开后不残留。
  3. Tab/Shift+Tab 跳过隐藏/禁用节点，删除焦点节点后回退确定；Enter/Space 激活一次，不依赖鼠标位置。
  4. 内容缩短或 viewport 改变后 offset 合法；嵌套滚动按合同消费；焦点项可滚入视野，分数 DPI 下命中无漂移。
- **证据与判定**：纯逻辑路由轨迹、布局/输入断言、目标平台真实鼠标/键盘/滚轮记录；在目标输入法记录 IME 事件与候选定位探针，将差异交给 M3 完整编辑验收。基础交互通过不等于 IME 已完成。

### M3 — 单行编辑与真实 IME

- **前置**：M2 焦点/捕获/滚动；Linux 目标系统输入法测试资源可用；单行编辑/IME 仍属 Alpha，多行仅在用户另行确认直接编辑原文后追加。
- **交付物**：TextInput 编辑模型、grapheme 移动/删除、选择和光标、剪贴板、最小撤销事务、IME preedit/commit/取消/候选定位；编辑实验台。
- **非目标**：富文本、完整代码编辑器、多光标、大文件；多行未经决策不计默认完成项。
- **验收**：
  1. 对 ASCII、中文、组合附标、emoji ZWJ、混合方向文本的既定用例，移动/删除不产生非法 UTF-8 或拆坏字符簇；点选、Shift/拖选与绘制选区一致。
  2. 复制/剪切/粘贴、只读/禁用、撤销/重做不重复回写；一组编辑动作重放得到精确期望字符串与 selection。
  3. 指定真实中文输入法中 preedit 可见但模型未提交，选词 commit 一次，Esc/失焦/删除节点按合同结束，不出现残留文字或 panic。
  4. 滚动、缩放、窗口移动/重排后候选窗口跟随实际光标；每个声称支持的平台有系统证据，而不只合成 Ime 事件。
- **证据与判定**：编辑逻辑用例、真实输入法名称/版本/桌面协议/操作步骤、过程截图或短录屏与结果；缺平台资源则该平台 IME 明确未验证，不得判全平台通过。

### 7.2 相对工作量与排程方式

M1 为高风险基础；M2/M4 为中高工作量；M3 的文字/IME 和 M6 的 Linux 原生协议/设备验证不确定性最高（额外平台另立合同）；M5 限定知识整理树图闭环，M7 的签名/分发取决于渠道。它们是相对复杂度，不是人日估算。先完成各阶段首个纵向切片，再用实际吞吐与缺陷率滚动估算剩余工作；平台数、IME 组合、多行与视觉变体是明确成本乘数，不把并行 agent 数等同于线性提速。

## 8. 测试金字塔与性能证据

### 8.1 分层验证

| 层次 | 关注点 | 证据边界 |
| --- | --- | --- |
| 纯逻辑，数量最多 | Signal/批处理/派生、代际、卸载、队列、selection、路由、调度时钟 | 不需要窗口；可证明状态机，不证明系统输入或 GPU |
| 布局与输入集成 | 真实字体测量、taffy 约束、滚动变换、焦点/命中、显示列表顺序与资源引用 | 固定字体与尺寸；合成事件仍不是系统事件 |
| 真实 surface 图形 | 运行 example，系统鼠标/键盘/滚轮、resize、DPI、截图 | 确认确实使用正式应用和 surface，不直接写 Signal 代替输入；软件/硬件适配器分开记录 |
| 平台系统测试 | 原生 IME、候选定位、剪贴板、读屏、窗口恢复、多屏 | 必须用对应系统服务；Xvfb 不能替代 Wayland、Windows、macOS 或真实输入法 |
| 性能/耐久，少而稳定 | 热路径、消息洪峰、资源回收、缓存峰值与长时间循环 | 独立基准，不用 debug 体感或单次平均值作性能承诺 |

### 8.2 图像回归与故障注入

图像测试登记窗口逻辑/物理尺寸、DPI、字体文件/版本、语言区域、主题、适配器/驱动/后端、渲染配置与依赖锁版本。固定光标闪烁/动画时间或在专门案例检查它；允许针对字体抗锯齿设局部容差，但容差必须在比较前确定，不能失败后放宽到通过。布局边界、语义和遮挡关系另做结构断言，不能仅凭一张“大致相似”的图。

跨平台建立各自基准，禁止用同一像素哈希要求所有驱动完全相同。差异超限保留差分与环境，人工确认后才更新基准。

现有 acquisition/调度注入属于纯逻辑。未来分别命名「错误分类测试」「Renderer 边界注入」「真实系统恢复试验」；在无安全可控方式诱发 GPU 故障时明确缺口，不为凑证据破坏主机会话或其他任务。

### 8.3 基准方法与预算形成

选中真实应用后，至少覆盖小型控件树、密集文字/滚动、动态增删、连续编辑/IME、后台更新突发和空闲。先记录硬件、构建 profile、驱动、采样时长与冷/热状态，再采集 p50/p95/p99 与峰值，而非编造“万节点 60 FPS”。需要区分事件时间、CPU 提交和实际呈现；测不到真实呈现就标明仅测提交延迟。

观察 Signal 通知/flush 数、dirty 节点与测量次数、布局/显示列表 CPU 时间、draw call/上传量、glyph/image 缓存、消息深度、RSS 与可获取的 GPU 资源指标。文字额外按可见、隐藏、裁剪外分类记录 prepare 次数/耗时和整形工作，分别控制可见量与总量，避免节点数稳定却有不可见工作或 renderer 高水位持续增长。CPU/RSS 不一定卸载后立即下降到原点，必须分辨存活引用泄漏、分配器保留与有界缓存；用逻辑计数、重复循环稳态和工具剖析交叉验证。

基于目标硬件的真实场景与用户体验要求提出预算，由主协调/用户确认后写入 M6 验收。预算达标后只做有证据的优化；达不到时先定位热点，再决定合批、虚拟化、缓存或依赖替换。

## 9. 协作、质量门禁与发布

本文规定后续交付方式，**不是授权本轮启动开发或编排**。沿用一任务一短分支、一 agent 一独立 worktree；并行前分配文件所有权，`ui.rs` 等共享热点先串行完成接口变更，避免多方同时改。跨模块任务先写小设计合同，不能各自发明一套 NodeId/事件协议。

后续实现每项 PR 应包含：目的与范围、依赖、公共 API 变化、可运行 example、回归测试、验证命令/结果、截图或系统证据索引、明确限制和回滚影响。由实现者之外的审查者 review；共用 GitHub 身份不冒充独立账户审批。main 为受保护集成线，禁止直接堆未审改动或 force-push。**历史配置已验证，本轮不改设置**：此前本线程已通过 GitHub 配置 API 核验，且实际约束 [PR #2](https://github.com/LuarAssassin/Chronobreak/pull/2) / [PR #3](https://github.com/LuarAssassin/Chronobreak/pull/3)：要求 PR、`Rust checks` 且 strict、管理员同受约束、禁 force-push/删除、线性历史、解决会话、仅 squash 合并、自动删除源分支。后续交付以服务端读回为准；此历史成果不替代未来配置核验。

基础门禁沿用现有命令：

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --examples --locked
```

CI 的精确 job 名为 `Rust checks`；新增平台/图形 job 应各自注明环境与能力，不把静态 Linux job 解释为系统图形认证。当前命令列在此作为后续合同，**本次文档任务没有执行它们**。图形改动补真实运行，编辑改动补 IME 系统清单，平台改动补相应设备记录。

合并默认 squash，保留清晰功能级历史；review 和必要证据通过后再同步 main、清理短分支/worktree。每里程碑至少交付一个可运行例子、一组回归、更新文档及限制清单，不允许只有库内部完成声明。

证据分两类：

- **长期精炼记录**：提交号、日期、机器/字体/后端、命令、步骤、预期/实际、结论、失败与限制、CI/PR 链接；必要的原创测试夹具和可复现脚本依项目审查决定纳入版本管理。
- **临时构建材料**：target、原始大日志、桌面录屏/截图和试验资源留隔离目录；review 完成后定向清理本次产物。先留下结论、环境、步骤及必要差分，不能删完仅留下不可核验的“通过”，也不依赖会过期的 `/tmp` 作为唯一说明。

禁止提交 secret、机器凭证、第三方全文/媒体和许可不明资源；不擅自打包系统字体。发布包、代码许可证、字体与资源许可、签名/安装方式只在用户决定后执行，`publish = false` 不因规划 M7 而自动更改。构建可运行与有权发布是不同门禁。

## 10. 风险与触发式决策

| 风险 | 可观察触发 | 处理与需升级的决定 |
| --- | --- | --- |
| 动态树陈旧身份/资源串用 | 删除后更新落入新节点、订阅或 renderer 缓存持续增长 | 暂停上层控件扩张，修代际/卸载协议；M1 失败不得绕过 |
| 通知重入与旧值回退（M1 优先） | A 收到 1 写 2，后注册 B 依次收到 2/1，pending=1 而 get=2；静态推导未重跑 | M1b 冻结入队/版本/通知与 flush 语义，按第 5.1 节回归最终 2；防 panic 不能代替一致性 |
| 输入与几何快照错序 | sync 后未 layout 即命中，外部更新/动态树让新属性与旧 bounds 混用 | M1b 确定提交/命中/呈现版本顺序，M2 回归布局变更后紧接输入 |
| 隐藏文字工作与索引缓存 | 隐藏仍 prepare，renderer 随历史节点高水位增长或槽位复用串字 | M1a 改可失效资源映射，M4 按可见性测 prepare/整形/上传及缓存稳态，不只数节点 |
| 文字/IME复杂度超预期 | 选区与字形不对应、候选错位、平台 commit 重复 | 拆最小复现并定位文字库/框架/平台层；缩减多行或平台范围需用户批准，不能把中文输入降为“以后”而照发同等承诺 |
| 队列洪峰/关闭卡死 | 队列持续增长、UI 饿死、关闭等待工作线程 | 有界通道、合并/背压、取消与期限；仅在有真实异步库需求时考虑运行时 |
| 顺序/颜色/分数 DPI 错误 | 合批后遮挡改变、alpha 光晕、文字与命中漂移 | 先回退优化，固定顺序与坐标/色彩契约，不用截图容差掩盖几何错误 |
| 平台验证债务 | 误把 Linux-first 当全平台已支持，或到 M6 才查原生 Wayland/IME | M1 开始 Linux 协议/设备探针，M2/M3 记录真实系统输入/IME；Windows/macOS 尚未实测，未来扩展另验 |
| 视觉/组件范围膨胀 | 工作台组件不断增加但主流程仍不能完成 | 以 D1 流程截断，新增组件必须说明阻塞的用户动作 |
| 性能与内存目标失焦 | 未有基准即重写文字/后端，或缓存增长不知上限 | 先采样与剖析，分离活资源/缓存；达到第 6 节证据门槛才提替换 |
| 无障碍后补成本 | 控件只有像素没有 role/action，焦点与系统语义分叉 | 从 M2/M4 维护行为与语义模型；M6 才集成系统桥接但不能才开始设计 |
| 许可与发布混淆 | 拟上传包但许可证、字体/资源授权不清楚 | 阻断分发，不阻断本地技术验证；由用户确认许可证与渠道 |

重大分岔的决策单至少包含：问题与最小证据、维持现状/局部补丁/替换的选项、对 API/迁移/平台/里程碑的影响、可逆试验和退出条件。用户只在真正改变产品边界或基础路线时选择，不需要批准每个内部函数；已获批准的 Rust/保留树/自绘/builder/Signal 技术栈不因小缺陷重新投票。

## 11. 近期最小行动包与维护规则

**已完成的文档工作**：M0 基线方案已交付，D1—D4 按正式答复回填；核心规格与主题方向入口联动。以下实现/合同工作均为 **计划，未启动**：

1. **先冻结 M1a 最小合同**：可失效 NodeId/作用域、卸载与文字资源映射；下一实现首切片仍是“挂一个 keyed 节点→排队更新→卸载→复用槽位→旧更新无效”，不直接跳做完整知识应用。
2. **M1b→M1c**：确定通知版本/flush 与几何快照顺序，回归 A/B 重入、keyed 重排及布局变更后紧接输入；再做有界入队→唤醒→UI flush→呈现。派生菱形仍是条件扩展。
3. **Linux 探针与 M2/M3**：冻结 X11/Wayland、字体/DPI、输入法/设备矩阵，Xvfb 用于确定性回归而非原生系统完成证明；M3 单行编辑/真实 IME 保留 Alpha 目标。Windows/macOS 仅保留架构可移植性，未实测。
4. **工作台首切片 M5a**：可先细化版本化 JSON schema/持久化合同与无私人资料 fixture，再按独立功能分支推进实现；M5b 等 M1/M2/M4 最小节点、连接线、裁剪/主题 API 到位后做自动布局与折叠，不先造自由画布或多行编辑器。
5. **网关实现前再问**：协议、baseURL、model、安全鉴权注入、发送告知与规模限额/超长文本处理；明确确认后才排 M5c 真实单次调用与 M5d 错误取消恢复，不读本机 key、不默认兼容协议、不自动计费重试。本轮不连接服务。

维护时每个里程碑保留状态、负责人、候选提交、验收项结果、证据位置和未解决限制；未完成项不可仅因合并代码变成完成。改变 D1—D4、加入条件项或替换依赖时同时更新依赖图、合同与支持声明，避免路线正文与实际交付分叉。下一次规划只细化最近一个里程碑，远期保留验收边界，不提前生成无限任务。
