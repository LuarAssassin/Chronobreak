# 明暗主题方向：冰青与炽红

## 1. 已确认的视觉方向

用户于 2026-11-12 23:58:33 America/Los_Angeles 确认统一自绘风格，并指定两组颜色：

- **明亮主题「冰青」**：凌波丽灵感的淡青蓝、白色、黄色；浅蓝承载按钮与选中背景，白色承载内容，深蓝灰负责阅读，黄色少量提亮。
- **黑暗主题「炽红」**：明日香灵感的黑色、红色、黄色；近黑承载工作区，红色承载品牌主操作，黄色少量强调及提示键盘焦点。

只借鉴战斗服与发色的颜色气质，不使用角色立绘、官方素材或宣称官方精确色值。主题名称与下面的数值是初始设计建议，颜色方向已确认；尚未实装进渲染层。两套主题共享组件、布局和交互语义，不另做逐平台原生皮肤或复杂动效系统。

## 2. 初始语义 token

色值均为不透明 sRGB。组件按语义读取 token，不把「红色」「浅蓝」硬编码为业务含义。

| Token | 明亮 | 黑暗 | 用途 |
| --- | --- | --- | --- |
| `background` | `#F7FAFC` | `#111318` | 工作区及导图底色 |
| `surface` | `#FFFFFF` | `#191D23` | 内容面板、侧栏 |
| `surface-raised` | `#EDF5F8` | `#242A32` | 菜单、浮层、对话框 |
| `text` | `#182B36` | `#F2F4F7` | 正文、标题、导图节点文字 |
| `text-muted` | `#4C626D` | `#ADB7C4` | 辅助说明与元信息 |
| `border` | `#CBD8DE` | `#3A444F` | 装饰分隔线与面板轮廓，不单独承担交互识别 |
| `primary` | `#B9E3F0` | `#CD4145` | 主操作按钮填充 |
| `on-primary` | `#173541` | `#FFFFFF` | 主按钮上的文字与图标 |
| `accent` | `#F4D35E` | `#E8C653` | 局部黄色强调 |
| `on-accent` | `#342B0D` | `#211B09` | 黄色填充上的文字与图标 |
| `focus` | `#00738A` | `#F0CD5A` | 焦点环、当前项明确指示 |
| `error` | `#B42318` | `#FF9C98` | 错误说明、图标和校验提示 |
| `success` | `#247342` | `#8AD2A0` | 成功说明与图标 |
| `selection` | `#D9EFF7` | `#4A282E` | 节点或文字的选中底色 |

选中文字沿用 `text`，`on-primary` 只与 `primary` 配对，`on-accent` 只与 `accent` 配对。需要新语义时增加有明确作用的 token，不给每个分类随意增添一套颜色。

## 3. 数值可读性基线

设计阶段用标准 WCAG 相对亮度公式在内存计算；主协调对以下关键组合独立复算。此处不是截图、GPU 合成或完整无障碍认证结果。

| 前景 / 背景 | 明亮对比度 | 黑暗对比度 |
| --- | ---: | ---: |
| `text / surface` | 14.61:1 | 15.35:1 |
| `on-primary / primary` | 9.44:1 | 4.73:1 |
| `on-accent / accent` | 9.57:1 | 10.31:1 |
| `focus / surface-raised` | 4.98:1 | 9.35:1 |

计算方法：令 sRGB 通道值 `c = channel / 255`，当 `c ≤ 0.04045` 时取 `c / 12.92`，否则取 `((c + 0.055) / 1.055)^2.4`；线性亮度 `L = 0.2126R + 0.7152G + 0.0722B`；对比度为 `(较亮L + 0.05) / (较暗L + 0.05)`。

普通正文及辅助文字以至少 4.5:1 为目标；必须承担识别作用的非文本边界/焦点指示以至少 3:1 为目标。透明度、悬停/按下/禁用态、真实渲染管线中的色彩转换须在实装时重新验收，不从静态 token 表自动推定通过。

## 4. 组件与导图使用规则

1. **浅蓝底不配浅色小字。** 明亮主题用深色正文和按钮字。浅蓝按钮与白面板的填充差异较小，默认增加 `text-muted` 描边或其他清楚的形状线索；不能只凭底色识别按钮。
2. **装饰线不是交互边界。** `border` 对 `surface` 的对比度约为 1.46:1 / 1.71:1，适合低强调分隔，不作为唯一输入框轮廓、复选框边界、展开指示或必要的导图连接线。必要线条优先使用 `text-muted` 并核验实际相邻底色。
3. **红色可以是正常操作。** 黑暗主题的“整理”按钮可用品牌红；错误另用 `error`、错误图标及具体文字。删除要有明确名称和图标，不仅靠换红色提示风险。
4. **黄色少量使用。** 不把整屏面板涂黄，不在亮底用黄色小字。强调填充与焦点环采用不同形状，避免混淆。
5. **选中与焦点分开。** 节点选中用 `selection` 底色加侧条/图标；键盘焦点另画可见环。初始建议 2 px 焦点环，并留 2 px 当前容器底色间隙；实装检查面积、裁剪及邻接对比度。
6. **主题切换只改样式。** 不重建业务文档或任务，不丢源文、生成树、选区、展开状态、滚动位置、已支持的缩放状态或正在进行的 LLM 请求。只对已实现能力作验收，不因列出未来状态而宣称相关功能已做。
7. **层级先靠布局。** 明暗主题使用相同的间距、密度、字号与节点布局；结构层次靠缩进、连接关系和字体层级表达，不依赖一堆分类颜色。

## 5. 实装切片与退出门槛

主题属于路线 M4，需求先落在同一个[知识整理工作台](knowledge-workbench.md)的最小节点和控件上，不为主题单开第二款应用。

- 先集中式主题 token 与样式失效，再接背景、文字、按钮、导图节点、选中及焦点；不提前造复杂继承式 CSS 系统。
- 在主题工作台案例中覆盖正常/hover/pressed/focused/disabled/error 的相关状态，再把规则复用到真实知识流程。
- 对实际合成后的正文、辅助文字、按钮、选中内容、输入轮廓和连接线验收对比度；以灰度或去色检查排除仅靠颜色传意。
- 用长中文标签和 1.0 / 1.5 / 2.0 DPI 检查文字、边界与焦点清晰度；主题切换前后布局和业务状态不应意外变化。
- 交付主题回归截图、键盘操作与状态保留记录，以及仍未支持的控件状态。数学对比度计算不能替代这一步。
