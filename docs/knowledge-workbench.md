# 知识整理工作台：Alpha 小核心

## 1. 定位与确认边界

用户于 **2026-11-12 23:58:33 America/Los_Angeles（2026-11-13T07:58:33.874Z）** 正式选择 D1 组件工作台，并要求结合真实知识整理用途：用思维导图/逻辑图承载粘贴内容的分级分类、整理、存储和显示，以业务压力验证 GUI 框架。这里是**一个有真实用途的组件/知识整理工作台**，不是两款独立应用，也不是完整 Obsidian/XMind/Dify。

D2 为 Linux 交付/验证先行，Rust/wgpu/winit 等跨平台架构不变；Windows/macOS 尚未实测。D3 为框架技术预览 Alpha，小步交付，非产品 Beta、无发布日期。D4 为统一自绘明暗主题：明亮取凌波丽灵感淡青蓝/白/黄，黑暗取明日香灵感黑/红/黄，仅借鉴战斗服与发色的颜色，不使用角色素材。初始语义颜色与可读性基线见 [主题方向](theme-direction.md)；具体色值仍需图形实装验收。

本文件是计划，不是功能完成声明。M0 基线方案已交付、方向已回填，M1 及以后均未实施；既有 19+1 测试只是历史证据。本轮不写功能代码、不运行构建、不改设置、不读取凭据、不连接服务或发送文本。依赖与框架验收见 [技术路线](technical-roadmap.md)，不在此重复。

## 2. 唯一主流程与非目标

用户主动点“粘贴”读取一段剪贴板文本 → 只读预览原文 → 明确点“整理” → 通过配置网关发起**单次请求** → 校验分级树结果 → 自动排布树形思维导图，节点可展开/折叠 → 本地保存 → 重启恢复，原文与生成结果都保留。发送前明确告知内容将发往配置网关；不监听或自动上传剪贴板。

先用只读源文预览控制范围，不先造完整多行编辑器；用户未来需要在应用内直接编辑原文时再确认。框架 M3 单行编辑/真实 IME 的 Alpha 目标仍保留，不能因业务首版绕开编辑而删掉。

**树图是核心载体**：首版自动布局节点及连接线，以展开/折叠和滚动浏览，不永久降格成纯文字列表；可读列表可作为错误诊断辅助。后续自由关系另议。首版不做自由逻辑图、任意画布/拖线、知识图谱、RAG、向量库、Agent 自主循环、自动浏览器、云同步、SQLite 或搜索。

## 3. 框架与应用边界

GUI 提供节点生命周期、滚动、布局、文字、主题、事件及连接线/裁剪等最小公开绘制 API；应用计算树的自动布局需求，通过公开接口表达，不能直接访问 Scene/Renderer 或手写持续重绘。若现有原语不足，向 M4 提交有限缺口，不把应用变成另一套渲染器。

prompt、LLM 客户端、知识文档 schema、组织分类规则与本地文件都属应用示例层，不污染 `Application`，不默认新建仓库或全局服务。I/O 不阻塞 UI；后台结果通过 M1c 有界消息入口返回，解析/校验与界面更新围绕该入口统一提交：可在线程外预解析受限数据，最终校验、请求版本检查及状态替换在 UI 消费消息时完成，不从工作线程修改 Signal/Scene。

## 4. 有限切片与依赖

### 切片 1 / M5a：schema 与本地保真

- 建议版本化 JSON 本地文档，记录原样源文、段落定位、生成树、折叠状态和最后有效结果；区分应用知识节点 id 与框架 NodeId。节点 id 稳定且唯一，`source_refs` 对应源文段落，分类容器可为空引用但不得伪造来源；细则实现前确认。
- 无 GUI 依赖，可先设计合同及无私人资料的固定 fixture，合同明确后按独立功能切片推进。校验版本、字段、根与父子关系、重复 id、树环、悬空引用和段落引用合法性，不合法结果不进入有效模型。
- 验收：同输入/schema 的 fixture 可回放；序列化往返原文逐字一致、生成树/id/引用和折叠状态保真；写入失败保留最后有效文件，损坏文件有明确错误。采用临时写入后替换等安全保存方案，具体文件位置/升级策略再定。

### 切片 2 / M5b：离线树图与展开折叠

- 依赖 M1a/M1b 的稳定身份/提交边界、M2 的事件/焦点/滚动及 M4 最小节点、连接线、文本、裁剪、明暗主题公开 API；不是等待无限控件库。
- 只加载明确标识“离线 fixture，未调用 LLM”的固定数据，自动布局树形思维导图；折叠状态由应用按知识节点 id 保存，隐藏与卸载遵守框架契约。
- 验收：节点/连线/裁剪一致，折叠再展开及重排不串状态，滚动可浏览；保存并重启仍保真。明暗切换不丢原文、树或折叠状态。Xvfb 可辅助确定性测试，但不代表原生 Wayland/实际 IME 全通。

### 切片 3 / M5c：剪贴板与真实网关单次调用

- 依赖 M5a/M5b、M1c 后台唤醒及最小剪贴板读取服务；剪贴板可先于完整 M3 编辑器接入，M3 自身验收不免除。
- **实现前再问**协议、baseURL、model、安全鉴权注入及发送告知方式；不假设网关 OpenAI 兼容，不读取现有网关或任何 key。配置/用户同意到位后才做真实调用验收，离线证据与真实服务证据分别记录。
- 验收：主动粘贴、只读预览、显式整理，仅一次请求；加载状态可见，返回树经校验再显示、保存并恢复，窗口休眠可被结果唤醒，无额外点击、无 UI 卡顿。

### 切片 4 / M5d：失败、取消与恢复

- 依赖 M5c，并扩展 M1c 的请求编号/代际、取消和关闭期限。可靠性规则从前面切片起生效，本切片补齐端到端故障矩阵，不是之前允许损坏数据。
- 验收：离线、超时、畸形 JSON、重复 id、树环/悬空引用均有清楚错误，保留最后有效结果；新源文即使已粘贴，也不能让失败结果抹掉旧有效文档。旧响应不得覆盖新请求；取消后晚到消息无效，关闭不无限等待。
- 无无限或自动计费重试，重试由用户再次明确触发。验证失败后仍能再次整理；保存失败可报告并保留内存有效结果，不伪报落盘成功。

## 5. 最小可信边界与待确认合同

模型输出只是待用户核对的整理建议，不当事实或执行指令；所有粘贴内容、prompt 中的资料和模型响应均当数据，不执行命令/脚本、不自动打开链接。fixture 不含私人资料；错误记录不默认泄露全文或鉴权信息。

待实现前确认：网关配置与安全鉴权注入、输出 schema/来源定位细则、文件位置与版本升级、取消/超时期限、节点/深度/响应大小/文本规模限额及超长文本提示或拒绝方式。解析须受限；先明确限额，不引入分块 RAG 系统。方向已确认不等于这些合同冻结。

**下一步**：框架仍先冻结 M1a 并实现最小生命周期纵切；工作台自身先做 M5a schema/持久化合同与 fixture。不要跳过身份基础直接堆完整产品，也不要以离线树图宣布 LLM 已接通。
